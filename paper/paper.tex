\begin{abstract}
    The Steiner Tree Problem in Graph (SPG) is a NP-Hard problem gathered much attention worldwide. 
    Genetic Algorithm (GA) is a simple yet efficient meta-heuristic optimizer that has been adopted in wide range of NP class problems. 
    In this paper, we investigated the efficiency of different diversity preservation techniques for GA in the context of SPG. 
    By using a fast implementation of bit string representation, appropriate searching operators, 
    we achieved a high-performance algorithm with low time cost. 
    We proposed two algorithms, the first one is relatively simple following principles of Eshelman\textquotesingle s CHC search.
    The latter, in attempt to strike a better balance between exploration and exploitation, applies a various number of techniques: Elitism Selection, Longest Distance elements, Dynamic Crossover Rate, Fitness Sharing, another definition for distance and an explicit procedure to reset population called ``Divergence''.
    Then, the algorithms are benchmarked with standard testsets, including large graphs from the SteinLib repository. Their performance are evaluated in two scenarios: original graphs and significantly reduced graph. 

\keywords{The Steiner tree problem in graph  \and Genetic algorithm \and Another keyword.}
\end{abstract}

\subsection*{Motivation}
\textbf{Nhu thay Tho noi nha anh em.}

Assuming we have a network system Q consisting of N different devices (referred to as nodes for convenience). 
The nodes are capable of establishing direct connections with other nodes in the network system, 
where node $Q_{i}$ is capable of establishing direct connections with nodes in the set $C \big(Q_{i} \big)$.
$\forall i \in \mathbb{N}, 0 < i < M \mid C \big(Q_{i} \big) \mid < M$.

We need to construct a routing system for that network such that all nodes in set T are interconnected, 
and the total cost of establishing connections between nodes is minimized.

From there, we can represent the network system as an undirected, weighted, connected graph G. 
The outcome is that the routing system will be a subtree in the graph that spans all nodes in set T. 
This is known as the Steiner Tree Problem in Graphs (SPG).

Given an weighted, connected, undirected graph \( G = (V, E) \), where \( V \) is the set of vertices and \( E \) is the set of edges. 

The objective of the Minimum Steiner Tree Problem is to find a subgraph \( T' \) of \( G \), where \( T' \) contains all vertices in \( T \) and has the minimum possible total weight. 
Specifically, the objective is to find a weight function \( w: E \rightarrow \mathbb{R}^+ \) such that the total weight of edges in tree \( T' \) is determined by:

\[
    \min \sum_{e \in E'} w(e)
    \]

where \( E' \) is the set of edges in tree \( T' \).

The problem belongs to the class of NP-hard problems. 
Therefore, there is no polynomial-time algorithm to solve it for all cases. However, there still exist efficient approximation algorithms to solve this problem in practice.

\subsection*{Problem Formulation, Notations and Terminology}
Later in this paper, we agree on some notations regrading SPG.

Given an undirect, weighted graph $G = (V,E)$ and a cost function $c$ mapping $c : E \mapsto \mathbb{R}^+$. A Steiner Tree for $(G,R)$, in which $R \subseteq V$ is the set of terminal vertices (or 'special', 'required' vertices), is a subgraph $T = (V(Y), Y)$ that \textbf{\textit{spans}} $R$ (i.e, $\forall s,t \in R$, there exists a path from $s$ to $t$ in $T$) with $Y \subseteq E$ is the subset of chosen edges and by $V(Y)$ we denote the set of vertices incident to the edge set $Y$.
The Steiner Minimal tree problem asks to find the tree $T^*$ with minimum sum of cost: $T^* = \arg\min c(T)$ with $$c(T) = \sum_{e \in Y} c(e)$$.
Traditionally, the set $S = V \setminus R$ containing additional vertices is called the Steiner set, and any $u \in S$ is called a Steiner node.

\subsection*{Introduction to Genetic Algorithm}


\textbf{Genetic Algorithm (GA)} \cite{yu2010introduction}is a heuristic algorithm that was invented by John Holland in 1975.
Inspired by the theory of evolution, GAs represent solutions as a chromosomes.
They create a population of chromosomes and perform genetic operations such as crossover and mutation 
to find the fittest individual of the population.


\textbf{Genetic Algorithm (GA)} comprises the following steps:

\begin{itemize}
    \item \textbf{Step 1}: Initialization: Create an initial population of chromosomes.
    \item \textbf{Step 2}: Selection: Select the individuals from the population.
    \item \textbf{Step 3}: Crossover: Create new individuals by crossover the selected individuals.
    \item \textbf{Step 4}: Mutation: Introduce random changes to the genes of the individuals.
    \item \textbf{Step 5}: Termination: If the termination condition is met, stop the algorithm. Otherwise, go to Step 2.
\end{itemize}

\subsection{Solution Representation}
Given the definition of SPG, any solution can be naturraly represented as a set of edges included in a Steiner tree.
This paper uses the traditional binary string encoding, with each bit 1 indicates that the corresponding edge is chosen. It follows that objective value computation is just simply the sum of choosen edges, i.e, the decoding has no ambiguity. What better is time needed per evaluation is linear to the number of edges. 

Compared to older approaches that use binary strings to represent the corresponding set of Steiner nodes, as can be seen in \cite{kapsalis1993solving,esbensen1995computing}, where they have to adopt some kind of interpretations from genotype to phenotype (the so-called decoder, which may also introduce some slight bias), our approach clearly has the advantage of not omitting any part of the search space.

However, it leads to some obvious disadvantages:
\begin{itemize}
    \item More time and space complexity for storage and calculations
    \item Exponentially larger search space
    \item A large part of the search space corresponds to some invalid solutions. From now we will refer to this with the term "toxic landscape"
\end{itemize}

Whether or not the tradeoff between increasing search space for not overlooking the global optimum is worth, it will be judged in Section \ref{experiment}

\subsubsection*{Efficient Implementation}
In order to reduce time complexity per each genetic operation, we adopt an efficient implementation.

An integer variable is essentialy a sequence of bits in computer memory. We used 64-bit unsigned integers to represent blocks of 64 consecutive bits of a binary string. This way, any gene is internally an array of 64-bit integers.

\begin{observation}
    Any gene that corresponds to a valid SPG solution contains no more than $|V|-1$ one bits.
\end{observation}

It's true due to the fact that a tree with $n$ nodes has exactly $n-1$ edges. In Algorithm \ref{alg:gene_iterate} is an efficient way to iterate through all set bit of a gene.

\begin{algorithm}[htb]
    \caption{$\texttt{bit\_traversal}$: traverse through set bits of a bitstring} \label{alg:gene_iterate}
    \KwData{A gene $Y$ internally represented as the array $A$}
    \KwResult{A list of position $p=\{i \mid Y_i = 1\}$}
    $i \gets 0$\;
    $p \gets \emptyset$\;
    $L \gets 0$ \Comment*[r] {the offset}
    \While{$i < |A|$}{
        $x \gets A_i$\;
        \While{$x > 0$}{
            $b \gets  \texttt{lsb}(x)$ \Comment*[r]{ least significant bit of $x$}
            $x \gets x \oplus 2^b$\;
            $p \gets p \cup \{ b + L\}$\;
        }
        $L \gets L + 64$\;
        $i \gets i + 1$\;
    }
    \KwRet{p}
\end{algorithm}

This implementation has time complexity of $\mathcal{O}(\max(|Y|, \frac{|E|}{64}))$ for a set $Y$ of choosen edges. Notice that bitwise operators on gene can be boiled down to operators on corresponding 64-bit-integer components. Later in this paper, we will show that other operations on a gene have similar implementation and thus have the same time complexity.

\subsection{Randomized Data Structures}
Introducing randomness in evolutionary algorithms has been proven to enhance the exploration capability and improving the efficacy of the search. \textbf{PLEASE CITE}. In this paper, two fundamental data structures and algorithms are used as ``atom'' in construction of other operators. They are Floyd-Warshall's shortest path algorithm \cite{floyd1962algorithm} and Kruskal algorithm for computing Minimum Spanning Tree (MST) \cite{kruskal1956shortest}. An improved \footnote{We use path-compressing and union by size heuristics to achieve inverse Ackerman constant factor, as analysed by Tarjan} Disjoint-Set Union-find (DSU) data structure \cite{tarjan1975efficiency} is used as a part of Kruskal algorithm.

To integrate smoothly in the system, these adopted data structures abuse the notation of genetic representation. Their products, which are shortest paths connecting any pair of vertices, and trees, are naturally sets of edges.

As the ``atom'' of the system, these two have great impact on the behavior of the operators built upon them. If the same shortest paths are included in almost any solution, or the lighter edges always supress the chances for heavier edges to be choosen, then the exploration capability of GA is limited significantly. The idea is, ``Smaller edges don\'t always belong to an optimal tree topology''. With that in mind, we modified the two data structures by introducing some randomness in both. 

For modified Floyd's algorithm, the indices in the outermost loop are permutated, i.e, the order of choosing the middle vertice $m$ in the formula $d_{i,j} \gets \min(d_{i,j}, d_{i,m} + d_{m,j})$, is random. For modified Kruskal's algorithm \ref{alg:mst} (named ``Almost Minimum Spanning Tree''), there is a probability that curent suitable smallest edge is skipped. The probability is named $$\texttt{rate\_of\_fluctuate}$$. Furthermore, to build the mutation operator, algorithm \ref{alg:mst} accept some \textit{bias} - a set of prioritized edges that is considered before all else. For this algorithm to work, the pre-condition is that all edges are sorted in increasing order of weight initially.

\textbf{Floyd Shortest Path gives the most impact on the whole algorithm and is the main cause for variety of the health of initial population. \cite{haouari2006hybrid} seems promising}

\begin{algorithm}[htb]
    \caption{$\texttt{almost\_mst}$: Almost Minimum Spanning Tree, modified from Kruskal's} \label{alg:mst}
    \KwData{Subgraph $Y$, rate of fluctuate $\epsilon$, bias set $B$}
    \KwResult{MST $T \subseteq Y$}
    $T \gets \emptyset$\;
    $D \gets$ DSU with size $|V|$ \Comment*[r] { assume DSU has interface: root, merge}
    \ForEach{$e = (u,v) \in B \cap Y$} {
        \If{$D.\texttt{root(u)} \neq D.\texttt{root(v)}$}{
            $T \gets T\cup \{e\}$\;
            $D.\texttt{merge(u,v)}$\;
        }
    }
    \ForEach{$e = (u,v) \in Y \setminus B$} {
        \If{$D.\texttt{root(u)} \neq D.\texttt{root(v)}$} {
            \If{$\texttt{random(0,1)} \ge \epsilon$}{
                $T \gets T\cup \{e\}$\;
                $D.\texttt{merge(u,v)}$\;
            }
        }
    }
    \Comment{Ensure connectivity because some edges maybe omitted}
    \ForEach{$e = (u,v) \in Y$} {
        \If{$D.\texttt{root(u)} \neq D.\texttt{root(v)}$}{
            $T \gets T\cup \{e\}$\;
            $D.\texttt{merge(u,v)}$\;
        }
    }
    \KwRet{T}
\end{algorithm}

\subsection{Self-correcting operators}
We apply two auxiliary routines for genetic operators, namely $\texttt{reduce}$ and $\texttt{make\_span}$.
\subsubsection*{reduce} takes inspiration from Kou's famous heuristic\cite{kou1981fast}. It is depicted in Algorithm \ref{alg:gene_reduce}

\begin{algorithm}
    \caption{$\texttt{reduce}$: Modified edge trimming heuristic} \label{alg:gene_reduce}
    \KwData{Subgraph $Y$ that spans $S$}
    \KwResult{a valid Steiner tree $T \subseteq Y$}
    $T \gets \texttt{randomized\_mst}(Y)$\;
    $Q \gets \emptyset$ \Comment*[r] {contains leaves of tree T}
    \While{$Q \neq \emptyset$}{
        $u \gets Q_0$\;
        $Q \gets Q\setminus \{u\}$\;
        \If{$u \notin S$}{
            $v \gets \delta(u)_0$\;
            $T \gets T\setminus \delta(u)$\;
            \If{$v$ \text{is now leaf of} $T$}{
                $Q \gets Q \cup \{v\}$
            }
        }
    }
    \KwRet{T}
\end{algorithm}

\subsubsection*{make\_span}, as the name suggests, corrects some genes correspond to a invalid solution by connecting the disjointed components by shortest paths, in a randomized order and topology. 

$\texttt{make\_span}$ only cares about components that contain at least one special node.
Another version of it - $\texttt{make\_span\_wide}$, considers all components.

\begin{algorithm}[htb]
    \caption{$\texttt{make\_span}$: Make subgraph span using shortest paths} \label{alg:gene_make_span}
    \KwData{Subgraph $Y$}
    \KwResult{Modified $Y$, spans $R$}
    $C \gets$ list of connected components of $Y$\;
    $T \gets$ random tree of $\{0,1,2,\dots, |C|-1\}$\;
    \ForEach{$(u,v) \in T$}{
        $x \gets$ random node $\in C_u$\;
        $y \gets$ random node $\in C_v$\;
        $Y \gets Y\cup\texttt{shortest\_path}(x,y)$
    }
    \KwRet{Y}
\end{algorithm}

\subsubsection*{Uniform crossover}
As Eshelman stated in \cite{eshelman1991chc}, crossover operators need to be effective (that also means ``disruptive''). We aim to adopt an operator that preserve good traits from both parent and generate children that are approximately ``in between'' them. Hence, Uniform Crossover \cite{syswerda1989uniform} is used.
Notice that children born from this have high chances to be invalid, the routine $\texttt{make\_span\_wide}$ is applied.
\begin{algorithm}
    \caption{Crossover operator} \label{alg:gene_crossover}
    \KwData{Two parents $A, B$}
    \KwResult{Children $C, D$}
    $C \gets A \cup B$\;
    \ForEach{$i\in C$}{
        \Comment{the loop follows the implementation as in \ref{alg:gene_iterate}}
        \If{$A_i \neq B_i$}{
            \If{$\texttt{random(0,1)} < 0.5$}{
                $C_i = 1 - C_i$\;
            }
        }
    }
    $D \gets A \oplus B \oplus C$\;
    $\texttt{make\_span\_wide}(C)$\;
    $\texttt{make\_span\_wide}(D)$\;
\end{algorithm}

\subsubsection*{Mutation}
This operator randomly flips a fixed percentage of \textbf{unset} bit in the gene, then is corrected via biased $\texttt{reduce}$ routine. The ratio of to-be-added edges is defined through the constant $$\texttt{rate\_of\_change}$$
Based on experimental study with multiple tweaked parameters settings, we found that this operator does not introduce much novelity to the population, and become more ineffective as the population moves towards the later phase. 
\subsection{Initialization population}
\textbf{PLEASE CITE} Initial solutions play an important role in an GA. The initial seeds need to be not only of adequate quality, to efficiently converge; but also lie in numerous regions of the search space, for better coverage over the search domain thus enabling global search capability.

We use 4 type of adopted heuristics, each with fixed percentage in the initial pool:
\begin{itemize}
    \item $\texttt{random\_heuristic}$ -- Get a random binary string for a gene then correct it
    \item $\texttt{stem}$ -- ``Grows'' the tree by incrementally adding edges to components containing terminal vertices
    \item Distance MST heuristic \cite{kou1981fast} gives the best quality in all of the initialization scheme proposed here, therefore act as a driving force for first few generations.
    \item ``Un-Greedy'' shortest path heuristic \cite{takahashi1980approximate} -- we modified the heuristic proposed by Takahashi. This heuristic first gets a permutation as a random ordering for $R$ (instead of getting the nearest vertex at each step), then connect nodes to the solution tree iteratively. 
\end{itemize}

\subsubsection{Sample Heading (Third Level)} Only two levels of
headings should be numbered. Lower level headings remain unnumbered;
they are formatted as run-in headings.

\paragraph{Sample Heading (Fourth Level)}
The contribution should contain no more than four levels of
headings. Table~\ref{tab1} gives a summary of all heading levels.

\begin{table}
\caption{Table captions should be placed above the
tables.}\label{tab1}
\begin{tabular}{|l|l|l|}
\hline
Heading level &  Example & Font size and style\\
\hline
Title (centered) &  {\Large\bfseries Lecture Notes} & 14 point, bold\\
1st-level heading &  {\large\bfseries 1 Introduction} & 12 point, bold\\
2nd-level heading & {\bfseries 2.1 Printing Area} & 10 point, bold\\
3rd-level heading & {\bfseries Run-in Heading in Bold.} Text follows & 10 point, bold\\
4th-level heading & {\itshape Lowest Level Heading.} Text follows & 10 point, italic\\
\hline
\end{tabular}
\end{table}


\noindent Displayed equations are centered and set on a separate
line.

schemas. Whenever possible, use vector graphics instead (see
Fig.~\ref{fig1}).

\begin{theorem}
This is a sample theorem. The run-in heading is set in bold, while
the following text appears in italics. Definitions, lemmas,
propositions, and corollaries are styled the same way.
\end{theorem}

Proofs, examples, and remarks have the initial word in italics,

\begin{credits}
\subsubsection{\ackname} A bold run-in heading in small font size at the end of the paper is
used for general acknowledgments, for example: This study was funded
by X (grant number Y).

\subsubsection{\discintname}
It is now necessary to declare any competing interests or to specifically
state that the authors have no competing interests. Please place the
statement with a bold run-in heading in small font size beneath the
(optional) acknowledgments\footnote{If EquinOCS, our proceedings submission
system, is used, then the disclaimer can be provided directly in the system.},
for example: The authors have no competing interests to declare that are
relevant to the content of this article. Or: Author A has received research
grants from Company W. Author B has received a speaker honorarium from
Company X and owns stock in Company Y. Author C is a member of committee Z.
\end{credits}
